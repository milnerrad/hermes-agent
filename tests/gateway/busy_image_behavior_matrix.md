## Implemented architecture and limits

- `gateway/busy_images.py` validates all attachments atomically under the source profile scope and reads bounded regular cache files using directory descriptors with no symlink following (including cache ancestors). It preserves native pixel bytes as data URLs; no auxiliary/image-generation model is called.
- `agent/image_steering.py` carries ordered native submissions through the existing string-compatible locked steer/redirect buffers. Only new checkpoint rows materialize image blocks. Original events remain attached only for the unconsumed fallback; they are not serialized into provider messages.
- Both normal and priority/photo ingress share the same runtime, protection and capability decision. A model-request correction cancels only that request; tool-phase correction uses the existing steer checkpoint. Steer mode never aborts a model request. Ownership/subagent/compression checks are repeated after background image decoding. A per-turn image-admission lock is acquired before any await so concurrent photo bursts cannot overtake a slower first decode.
- Supported immediate path: native image mode, positively vision-capable model, in-process `chat_completions` or `codex_responses` runtime exposing the image-control method. Unknown/text-only models, Codex app-server/proxy/older runtimes, tool image mode, unsupported formats and mixed media keep the original queue path. A later loss of vision capability defers unconsumed image submissions instead of injecting unsupported blocks or a caption-only substitute.
- Busy admission is bounded to 20 MiB total source-file bytes and 40 million pixels per image; accepted source formats are PNG/JPEG/GIF/WebP. Oversize, invalid, unavailable, linked or outside-cache files use existing queued-media handling. No new configuration or dependencies.
- Explicit `/stop` retains existing hard-cancel semantics: pending corrections are superseded, not resurrected as surprise follow-up turns. Request-only redirect cancellation, retry/fatal-exit and late-checkpoint paths preserve unconsumed image events. Generic FIFO order is unchanged.
- Source acceptance is offline only. The SDK request test decodes real red/blue fixture pixels from the captured OpenAI Responses request generated by the production Codex transport. It proves native request projection, not a live provider's visual interpretation. Live Telegram/provider validation remains deferred.
